GPU 崩溃正面解决方案 — 决策文档

2026-07-23 · 依据:BUG-0002 / BUG-0003 归档 + 三份诊断分析 + 同行调研(带引文)+ 本机实测 · 状态:待用户决策,未写任何产品代码

1. 问题与证据摘要

要解决的问题:macOS Apple Silicon 上 Electron 39 的 ANGLE-Metal GPU 进程崩溃(SIGTRAP,CommandEncoder::reset NSArray 异常)。本机 3 天 3 次(.ips:07-20 15:10、07-23 10:32、07-23 14:27),另一台机器 07-23 05:52 一次。崩溃后果经 BUG-0003 链放大为「花屏且切 tab 无法自救」。

已确认的触发面:遮挡边界的渲染管线状态翻转 —— 唤醒(+30ms)、watchdog L1 解除节流(+14ms)、历史上的批量 WebGL dispose。均为低概率触发、高确定后果。

上游根因(electron#49904 讨论定位):ANGLE Metal mPendingSignalEvents 向量中出现 nil 条目,Metal 编码 signal event 时 NSArray 插入抛异常。nil 从何而来上游未完全定案,无已确认的上游修复 CL。

2. 关键事实核查结果(决定方案走向)

#事实核查方式对方案的影响
F1electron#49904 已于 2026-03-04 以 Completed 关闭;Cursor 的处方 = Electron ≥39.5.2 + 去掉 --disable-skia-graphite调研(github issue 原文)纠正了我们归档里「关闭无修复」的旧结论
F2我们已经在 Graphite 上:裸 Electron 39.8.5 本机实测 skia_graphite: enabled_on / skiaBackendType: GraphiteDawnMetal;生产 GPU 进程命令行无任何 Graphite 禁用开关本机 Electron 探针 + ps 读运行中 GPU Helper 参数#49904 处方对我们不适用 —— Cursor 的崩溃在 Skia-Ganesh 访问路径,我们的崩溃经 WebGL 生产者侧 eglReleaseTexImage 触达同一 nil 缺陷,Graphite 绕不开(终端 6 个 WebGL canvas 是重度用户)
F3Electron 39 已于 2026-05-05 EOL;最新受支持:41.10.3 / 42.7.1 / 43.2.0(Chromium 146/148/150);39 线最后补丁 39.8.10(我们 39.8.5)调研(releases.electronjs.org / endoflife.date)大版本升级无论如何都是必做项;它同时是「上游可能已修」的唯一顺风车
F4setBackgroundThrottling(false) 作用于遮挡/最小化窗口造成 visibility 失同步 = Electron 已知 bug(#50250 + PR #39223)调研(github issue/PR 原文)watchdog L1 干预是已知 bug 触发器 → 撤除遮挡窗口上的干预有上游背书
F5Chromium 自带 GPU 崩溃次数熔断:约 3 次后逐级降到软件渲染,栈耗尽则浏览器进程主动崩溃(content/browser/gpu/fallback.md)调研(Chromium 源码文档)我们的恢复设计必须与这个熔断共存;高频崩溃日 Chromium 可能已把用户降到软件渲染
F6VS Code 阶梯 = WebGL → DOM;context-restored 路径不可信(vscode#263159 复原失败,closed not-planned),dispose+recreate 才可靠;xterm 官方也推荐 onContextLoss → dispose调研(vscode issues / xterm README)App 层降级方向与同行一致;我们已有的 context-loss 冷却 + DOM 回退基础设施方向正确,可扩展
F7Electron 默认禁用 MacWebContentsOcclusion(生产 GPU Helper 命令行可见,非我们设置)ps 实测本机 hidden 状态来自 Space 切换/应用隐藏(窗口离屏),是无歧义的合法 hidden → watchdog 误报结论更实

3. 当前架构 vs 目标架构

当前(07.22)

Electron 39.8.5(EOL)·ANGLE nil 缺陷在场
watchdog 对遮挡窗口翻状态(L1/L2)= 崩溃触发器 + #50250 失同步触发器
崩溃后:隐藏态重建 → 挂回污染共享图集 → 花屏,切 tab 无效
降级:仅 context-lost 冷却;GPU 崩溃不触发 DOM 回退

目标

Electron 受支持大版本(41/42/43)·上游 8 个大版本的 ANGLE 修复顺风车
watchdog 只在「用户能看见窗口」时干预;遮挡=合法态,零状态翻转
崩溃后:换新共享图集 + 重建延迟到可见 + 完好性回读
会话内 GPU 崩溃 ≥N 次 → 终端粘性降级 DOM(VS Code 对齐),提示可重启恢复

4. 方案分层与选项

层 H — 正面消除崩溃(上游缺陷本体)

选项内容评估
H-A Electron 大版本升级 推荐39.8.5 → 受支持大版本。候选:41.10.3(最保守)/ 43.2.0(最新稳定,Chromium 150)。升级后用 § 7 的压力验证做 before/after 崩溃率对比。唯一现实的「上游修复顺风车」;39 EOL 本来就必须走。成本:native 模块(node-pty/@parcel/watcher)重编、xterm 补丁核对、全量回归。风险:无上游修复 CL 的直接证据,升级后崩溃可能仍在(概率性收益)—— 所以必须配 § 7 验证与 H-C 兜路。
H-B 自补 ANGLE + 自编 Electron 重在 mtl_command_buffer.mm 对 nil signal event 加防御(跳过/守卫),自维护 Electron 构建。最"正面",但要自建并长期维护 macOS arm64/x64 的 Electron 构建流水线(编译数小时、签名、随每次安全更新重打)。仅当 H-A 验证后崩溃仍高频才值得;也可作为向上游提交 patch 的载体(H-D)。
H-C 收缩应用内 WebGL 崩溃面 推荐(与 H-A 并行)①移除我们自己的触发器(见层 W);②会话内 GPU 崩溃 ≥N 次(建议 N=2)→ 终端粘性降级 DOM 渲染并提示(复用现有 webglFailureCount/冷却/DOM 回退基础设施,VS Code 对齐);③保留 ONWARD_* 强制 DOM 的诊断开关。不依赖上游;把「崩溃 → 花屏循环」变成「崩溃 → 稳定的 DOM 渲染」。代价:DOM 渲染的滚动/高吞吐性能低于 WebGL(仅在降级后承受);需一条降级横幅文案(en+zh-CN)。
H-D 上游反哺 长线把我们的 .ips + 遮挡翻转压力复现器整理成 ANGLE/Electron issue,附 nil-signal-event 分析。成本低(材料现成),收益慢;与 H-A/B/C 均不冲突。

层 W — watchdog 语义修复(BUG-0002,双重收益:消误报 + 拆崩溃引信)

W1 遮挡/离屏 hidden = 合法态,mismatch 仅当「窗口对用户可见(hasFocus / 前台)而文档 hidden」;W2 win.on('focus'/'show') 触发立即复检 + 冷却失效;W3 非前台窗口禁止一切干预(L1 的 #50250 风险 + L2 的帧驱逐都被移除);W4 渲染侧「输入到达但文档 hidden」即时自报。

层 R — 崩溃恢复正确性(BUG-0003)

R1 恢复时强制换新共享图集(GPU 侧纹理已全灭,保留旧对象零收益)+ 重建延迟到 document-visible;R2 根治补丁内图集重绑定记账(专项,消除普通 tab 切换的脏引用);R3 恢复后完好性像素回读(P0 插桩)超阈值自动再修一次。注意与 Chromium 崩溃熔断(F5)协同:我们的恢复不应对抗软件渲染回退。

6. 推荐组合与实施顺序

推荐:H-A + H-C + W + R1(先行)→ R2(专项)→ H-D(顺手)。H-B 暂缓,仅当升级后崩溃率不降再评估。
  1. 第一批(小、快、独立于升级):W1–W4 + R1 + P0 插桩(崩溃相关性字段、图集回读)。当前 39.8.5 上即可发,立刻止血「花屏 + 黑屏」两条用户可见链。
  2. 第二批:H-C 的粘性 DOM 降级(N=2)+ 降级横幅(en+zh-CN)。
  3. 第三批(专项):Electron 升级(候选版本待定)+ § 7 A/B 验证;R2 图集根治随 xterm 补丁核对一并做。

7. 验证方案(升级/修复的 before/after 都用它)

  • 压力复现器(新增,amend 现有 RCS runner):遮挡翻转风暴 —— 脚本驱动窗口 hide/show/Space 等价切换 + setBackgroundThrottling 开关 ×N(N≥200),计数 main:gpu.process-gone。当前构建先取基线,任何修复/升级后同参数复跑。崩溃是概率事件 → 用次数换统计功效;N 与判定阈值按首轮基线定。
  • 生产遥测:error/gpuProcessCrash(已有)按版本分桶,升级灰度后看崩溃率曲线;P0 相关性字段(msSinceLastThrottleToggle / msSinceLastUnocclude / msSinceLastNudge)让每次崩溃自带归因。
  • 正确性门:RCS 全套(ATLAS/EPOCH/TRANSIENT/STAG)+ 新增 RCS-GPU-01(模拟崩溃 → 恢复 → 逐单元格 ground-truth → tab 往返复查);W 层配 VHM 单元用例 + IWD autotest 断言(N=5 内部聚合)。
