  • OSC 回滚先提取纯逻辑，能够直接覆盖“旧 rejection 不得删除新值”。

不应继续沿用的做法

  • 只在 prefetch 响应完成时看 selected file：仍留有 discard 与 cleanup 之间的窗口。
  • TTM-32 用固定 sleep 等待 rejection：不能形成确定性同步。
  • History 只看 debug API 的 isOpen()：旧 API 可能仍返回 true，但可见 host 尚未真正恢复。
  • 单纯放宽 cwd 或 runner timeout：会掩盖同步缺陷，违反 300 秒 runner 上限原则。
